- (decision) AD-1 Enforcement is app-layer only: all whitelist enforcement lives in the mitmproxy Python addon (hooks tls_clienthello for SNI read/policy, requestheaders for action via Flow.kill() or Response.make(403)). No host iptables/network backstop in scope. User chose mitmproxy as the single gate.
- (decision) AD-2 Enforcement act (Flow.kill / 403) happens ONLY in requestheaders, never in tls_clienthello. Context.kill() and Connection.kill() do not exist in current mitmproxy; only Flow.kill(). Blocked hosts receive a real HTTP 403, not a TCP reset.
- (question) ACCEPTED RISK (consequence of AD-1): enforcement is cooperative. Bun honors HTTPS_PROXY so opencode routes through the proxy, but an agent with a shell + curl can bypass it and reach the internet directly; Kata installs no host-side egress filtering. Documented, not mitigated.
- (decision) AD-3 CA trust: mitm CA is installed into the guest SYSTEM trust store (/usr/local/share/ca-certificates/ + update-ca-certificates). SSL_CERT_FILE must never point at the mitm CA alone — OpenSSL REPLACES the default bundle (hard if/else in crypto/x509/by_file.c), breaking all public HTTPS. NODE_EXTRA_CA_CERTS is additive and is the only var opencode's Bun runtime reads.
- (decision) AD-4 Proxy reachability is by fixed IP on a dedicated bridge (10.211.0.10:8080), never Compose service-name DNS — kata#6688 makes 127.0.0.11 unavailable inside the Kata VM. HTTPS_PROXY is a literal value in the guest env contract; the bridge subnet and proxy address are ONE owned value.
